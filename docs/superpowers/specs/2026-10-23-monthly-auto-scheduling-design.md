# 월별 자동 시험 일정 편성 설계

작성일: 2026-10-23, 한국시간 기준

상태: 요구사항 반영 설계서 작성 완료 · 사용자 문서 검토 대기 · 제품 코드 미구현

## 1. 목적과 확정된 요구사항

시험항목별 총 필요 가동시간을 저장하고, 사용자가 선택한 월의 시험 목록을 지정한 시험실에 자동 편성한다. 기존 `시험 계획 수립`과 수동 등록·수정·실적·캘린더·CAPA·계정 기능을 삭제하거나 대체하지 않는다. 독립 메뉴 `자동 시험 일정 편성`을 추가한다.

사용자와 대화로 확인한 기준:

- 시간은 필요 가동일수가 아닌 **총 필요 가동시간**으로 관리한다.
- `빠른 배치`와 `완료 희망일 기준`을 사용자가 선택한다.
- 앱을 사용하는 현재 시각 이후만 편성하며, 이미 지난 시간으로 소급 등록하지 않는다.
- 일반 시험도 같은 시험실의 이어지는 운영일에 배치한다. 월요일의 가동 가능한 시간을 사용하고 화요일에 남은 시간을 이어 가동한다.
- 다른 시험의 빈 시간들을 모아 월요일·수요일·금요일처럼 임의 분할하지 않는다.
- 기존 운영시간·휴식·공휴일·주말·연속시험·중복 허용 예외를 유지한다.
- 기존 예약은 자동 이동·수정·삭제하지 않는다.
- 자동 등록 전에 미리보기와 사용자 확정을 거친다.

아래의 UI·저장 방식·안전 장치 세부 사항은 이 요구사항을 구현하기 위한 제안이며, 본 문서 검토 후 확정한다. 시험항목별 실제 기준시간은 아직 제공되지 않았으므로 관리자 입력 전까지 미등록으로 둔다.

## 2. 접근 방식

권장: 기존 가동 규칙과 검증 함수를 재사용하는 별도 계산 모듈을 추가하고, 검토한 편성안만 기존 예약 저장 흐름으로 등록한다. 계산 결과를 재현할 수 있고, 수동 기능과 분리해 단계적으로 검증할 수 있다.

대안 비교:

- 과거 자동 배치 기능 복구: 과거 문서는 가동일수와 시험실 자동 선택 기준이다. 이번의 시간 단위·지정 시험실·두 모드·현재 시점 이후 조건과 달라 그대로 복구하지 않는다.
- 외부 AI/최적화 서비스 사용: 이번의 명시적 가동 규칙에는 별도 서비스가 필요하지 않다. 새 API 키나 외부 데이터 전송 없이 처리한다.

기준시간의 저장은 사용자가 입력한 값을 관리하는 것이며, AI가 시험 소요시간을 추측하거나 기존 실적으로 자동 변경하는 기능은 포함하지 않는다.

## 3. 화면과 권한

### 기준시간 관리

관리자가 기존 `운영 설정`에 추가되는 기준시간 표에서 관리한다. 기존 운영 설정 항목은 유지한다.

- 행 식별: 시험실 ID + 시험항목. 현재 `EQUIPMENT`에 허용된 조합만 사용한다.
- 값: 총 필요 가동시간, 사용 여부. 시간은 양수의 0.5시간 단위로 입력하고 내부에는 정수 분으로 저장한다.
- 같은 시험항목이라도 시험실별로 다른 기준시간을 설정할 수 있다.
- 현재의 모든 허용 조합을 표시하되 초기 시간은 비워 둔다. 0시간이나 가상의 기본 시간을 넣지 않는다.
- 기준 변경은 기존 예약·실적·기준계획을 소급 변경하지 않는다.

### 자동 편성 입력

활성 팀 계정이 별도 메뉴에서 사용한다.

- 대상 월, 배치 방식.
- 시험 목록: 프로젝트, 시험항목, 지정 시험실, 담당자, 총 필요 가동시간, 선택적인 주말 포함, 완료 희망일.
- 지정 시험실에서 가능한 시험항목만 선택한다. 다른 시험실로 자동 변경하지 않는다.
- 등록된 기준시간을 불러오며 해당 편성 행에서만 시간 변경이 가능하다. 행의 시간 변경은 관리자 기준표를 바꾸지 않는다.
- 필요한 기준시간이 없으면 입력을 요구하고 편성을 진행하지 않는다.
- 완료 희망일은 `완료 희망일 기준`에서 필수이며 빠른 배치에서는 사용하지 않는다.
- 입력 행은 최대 30개로 제한한다. 각 행은 하나의 시험이며 행 간 선후관계는 두지 않는다.
- 비활성화된 계정은 새 담당자로 지정할 수 없다.

### 미리보기와 확정

시험실, 시험항목, 담당자, 요구 가동시간, 시작·종료 일시, 운영일별 구간, 계산된 총 가동시간, 희망일 준수 여부를 표시한다. 시간은 한국시간으로 표기한다.

미배치 항목은 부족한 시간·기간 제한·예약 충돌·설비 정지·공휴일 자료 미확인 등 원인을 표시한다. 모든 항목의 배치가 성공한 경우에만 일괄 확정을 허용한다. 일부 항목만 조용히 등록하지 않는다.

입력을 변경하면 기존 편성안을 무효화한다. 미리보기를 닫거나 메뉴를 바꾸는 것만으로 DB에 시험을 등록하지 않는다.

## 4. 시간 범위와 두 배치 모드

서버 시각을 신뢰 기준으로 삼고 한국시간(UTC+9)의 월 경계를 계산한다. 브라우저가 보내는 현재 시각으로 검증을 우회할 수 없다.

- 시작 하한은 `선택 월의 시작`과 `서버 현재 시각 이후의 30분 경계` 중 늦은 값이다. 정각 경계에 실행해도 이미 진행 중인 슬롯을 쓰지 않으며, 확정 시점에 시작이 과거가 되면 다시 편성한다.
- 과거 월은 자동 편성하지 않는다. 다음 달을 선택하면 그 달의 첫 가능한 운영 구간부터 찾는다.
- 종료 상한은 선택 월의 다음 달 1일 00:00이다. 자동으로 다음 달로 넘기지 않는다.
- 날짜로 입력한 완료 희망일은 한국시간 해당 날짜의 끝까지 포함한다. 허용 종료 상한은 월말과 희망일 중 이른 값이다.

### 빠른 배치

사용자가 나열한 순서로 각 지정 시험실의 가장 빠른 연속 가동 가능 구간을 찾는다. 시험실이 다른 행들은 같은 시간에도 배치될 수 있다. 같은 조건과 데이터에는 같은 결과를 제공한다.

### 완료 희망일 기준

희망일이 빠른 시험을 우선하고 같은 날짜이면 입력 순서를 유지한다. 각 시험은 현재 시점 이후부터 희망일 전에 완료되는 가장 빠른 연속 구간을 찾는다. 희망일이 촉박하다고 과거에 배치하거나 운영 규칙을 완화하지 않는다.

두 모드 모두 지정한 시험실을 유지하며 기존 일정은 변경하지 않는다. 첫 버전은 전역 최적 배치를 보장하지 않는다. 1회 편성의 계산 탐색은 최대 3초 또는 후보 100,000개까지로 제한한다(공휴일 API 대기 시간은 별도). 한도에 도달하면 `탐색 한도 내 편성안을 찾지 못함`으로 표시하고 수학적으로 배치 불가능하다고 단정하지 않는다. 계산은 작업 단위로 이벤트 루프를 양보하여 다른 팀원의 조회를 장시간 막지 않는다.

## 5. 연속 배치의 정의

### 일반 시험 및 운영시간 적용 시험

시작한 날의 남은 가동시간을 사용하고 다음 운영일의 시작부터 이어 가동한다. 중간 운영일은 필요한 운영시간을 연속 사용하고 마지막 날은 필요한 잔여 시간만 사용한다. 기존 규칙이 정하는 휴식·야간·비운영 요일·공휴일은 필요한 가동시간에 포함하지 않는다. 휴일을 건너뛰는 것은 자투리 시간 분할로 보지 않는다.

예: 기본 운영 설정이 08:30~20:30, 휴식이 12:30~13:30 및 17:30~18:00인 평일에 15시간 시험을 월요일 08:30에 시작한다면 월요일 10.5시간, 화요일 4.5시간으로 화요일 14:00에 마친다. 이 예시는 기본 운영 설정의 산술 검증용이며 실제 사용자 설정을 덮어쓰지 않는다.

다음 운영일에 기존 시험이나 설비 정지로 이어 가동할 수 없다면 그 뒤의 빈 날로 뛰어넘지 않는다. 해당 시작 후보 전체를 버리고 다른 시작 시각에서 다시 찾는다. 중간에 다른 시험을 끼워 넣어 쪼개지 않는다. 단, 아래의 기존 동시 가동 예외는 그대로 적용한다.

### 기존 예외 보존

- 단품 대상내구 시험 및 SN 커브 추출시험: 야간·주말·공휴일을 포함한 실제 연속 24시간 가동.
- 같은 시험실의 성능시험: 기본 운영시간·휴식·운영일·공휴일 제외 적용.
- 열가진의 열피로·열충격·열피로/열충격: 기존과 같이 운영일·운영시간 안에서 휴식시간을 가동시간에 포함. 이를 24시간 시험으로 바꾸지 않는다.
- Glass Wool 내구: 열가진 #1/#2의 기본 운영시간·휴식·공휴일 제외 적용.
- 주말 포함: 현재 허용된 엔진동력계 #1/#2와 유동저항 시험실에만 명시적으로 적용한다. 자동으로 켜지 않으며 공휴일까지 포함시키지 않는다.
- 같은 엔진동력계에서 배압 시험과 토출/방사음 시험이 서로 겹칠 수 있는 기존 예외는 유지한다. 같은 시험 종류 중복 및 그 외 금지된 중복은 차단한다.
- 충돌 판단은 현재 예약 점유 구간 기준을 유지한다. 휴식 때문에 실가동이 0이라고 다른 시험의 점유 구간을 임의로 사용할 수 없다.
- 해당 연도의 공휴일은 기존 한국천문연구원 API/캐시/내장 자료 및 사용자 추가 휴일 흐름을 재사용한다. 일반 시험의 필요한 연도 자료가 미확인 상태이면 경고 후 확정을 막는다.

## 6. 기존 예약 표현과의 차이 및 호환 설계

현재 `expandReservation()`은 일반 다일 예약에 매일 동일한 시작/종료 시간대를 적용한다. 따라서 월요일 전체 시간과 화요일 잔여 시간만 예약하는 표현을 기존 start/end 값만으로 저장하면, 잘못된 가동시간·중복 검사·CAPA가 발생할 수 있다.

이를 피하기 위해 새 자동 편성 예약에만 검증된 일별 `plannedWindows`를 추가하는 확장 방식을 제안한다.

- 시험 한 건은 예약 한 건으로 표시한다. 일별 구간을 각각 별개의 시험으로 늘리지 않는다.
- start/end는 전체 시작과 최종 종료를 나타내고, plannedWindows는 실제 예약 점유 구간을 나타낸다. 휴식 차감 등 실가동 계산은 기존 시험별 규칙을 적용한다.
- 일별 구간은 서버에서 생성한다. 허용 시험실·정렬·중복·기간 경계·30분 단위·연속 운영일·요구 가동시간 일치 여부를 검증한다. 클라이언트가 임의의 구간을 보내 검증을 우회하지 못하게 한다.
- 새 구간이 없는 기존 수동/과거 자동 예약은 기존 함수 결과와 동일해야 한다. 과거 자동 배치의 automaticPlan 메타데이터와 DB 행은 해석을 바꾸거나 복원하지 않는다.
- 캘린더, 검색, 중복 검사, 설비 정지 검사, 가동시간, CAPA, 내보내기, 오늘 팝업, 최초 계획 이력에서 같은 구간 해석을 사용한다.
- 최초 등록 이력에는 당시 검증한 구간을 저장한다. 최초 등록자는 자동 편성을 확정한 로그인 계정이며 담당자와 구분한다.
- 새 자동 예약의 이름·프로젝트·담당자·비고 수정은 기존 화면에서 계속 가능하다. 날짜/시험실/종류를 수동 변경하면 연속 운영일 구간을 서버에서 재계산하고 변경 사유와 변경 후 가동시간을 표시한다. 기존 기준시간은 소급 적용하지 않으며 자동 편성 당시 요구시간은 이력용으로 남긴다.
- 실적 입력은 실제 시작/종료와 기존 실적 규칙으로 계산한다. 계획의 구간 배열을 그대로 복사해 실제 시간을 잘못 계산하지 않도록 별도 검증한다. 이미 실적이 있는 시험의 기간/설비 등 변경 제한은 유지한다.

## 7. 구성 요소와 저장

- `src/schedule.mjs`: 기존 가동 규칙의 단일 기준을 유지하고 새 구간 표현을 검증/해석하는 경로를 추가한다. 기존 수동 예약 경로는 보존한다.
- 별도 계산 모듈: 시간표, 현재 시점, 선택 월, 입력 행, 기존 예약, 설비 정지, 휴일을 받아 두 모드의 편성안을 만든다. 미리보기 계산 중 운영 DB에 시험을 쓰지 않는다.
- `src/store.mjs`: 기준시간 저장, 편성안 일괄 등록, 기존 저장 검증 재사용 및 구간/이력 일관성 보장.
- `server.mjs`: 관리자 기준시간 API와 활성 팀원용 미리보기/확정 API. 기존 수동 API는 유지한다. 과거 제거된 경로를 무심코 다시 활성화하지 않는다.
- `public/index.html`, `public/app.js`, 필요 시 `public/styles.css`: 별도 메뉴, 목록 입력, 기준시간 관리, 미리보기와 확정 결과 표시.

기준시간은 서버 설정 데이터로 저장하고 버전을 관리한다. 새 편성 등록 이력은 구형 automatic_plans와 구분되는 새 저장 영역으로 보존한다. 기존 전체 일정 일괄 삭제는 새 편성 등록 이력도 삭제하되 기준시간 설정은 보존하도록 검증한다. 개별 시험 삭제는 기존 관리자/최초 등록자 권한과 백업을 유지한다.

## 8. 미리보기·확정 안전 장치

- 미리보기는 사용자별 식별자로 서버에 보관하고 30분 후 만료한다. 서버 재시작 시 다시 생성해야 한다.
- 확정 요청은 생성한 사용자만 보낼 수 있다. 임의의 예약 배열을 확정 API에 제출할 수 없게 한다.
- 기준시간, 현재 운영 규칙, 공휴일, 기존 예약/실적, 설비 정지, 계정 상태 및 입력 스냅샷을 보관한다. 관련 데이터가 달라지면 재편성을 요구한다.
- 확정 직전에 서버 현재 시각을 다시 검사한다. 이미 지난 시작이 포함된 편성안은 자동 이동시키지 않고 다시 생성하게 한다.
- 모든 예약과 점유 구간·최초 이력·일괄 등록 이력을 하나의 SQLite 트랜잭션으로 저장한다. 최종 검증 실패 시 전부 롤백한다.
- 같은 편성안의 재확정 요청은 기존 결과를 반환하고 중복 등록하지 않는다. 확정 후 서버 재시작에도 중복 방지 결과를 보존한다.
- 생성된 시험은 기존 화면에서 조회·수정·실적 입력·권한에 따른 개별 삭제가 가능하다. 기존 시험과 확정 기준계획을 소급 변경하지 않는다.
- 모든 변경 API는 인증과 CSRF를 검사하고, 비동기 처리 후와 트랜잭션 직전에도 계정·권한이 유효한지 재검사한다.

## 9. 검증과 배포

구현 전에 실패하는 테스트를 추가하고 이후 통과시킨다. 최소 검증 범위:

1. 총 필요시간 정확성, 0.5시간 단위, 미등록 시간 차단.
2. 15시간 시험의 첫날 전체/다음 날 잔여 배치, 현재 시점 중간 시작, 휴식 중 현재 시점.
3. 주말·공휴일·대체공휴일·설비 정지·휴식 및 기존 연속/동시 가동 예외.
4. 중간 운영일 충돌 시 후보 전체 재탐색, 임의 분할 및 다른 시험실 변경 금지.
5. 두 모드의 순서/희망일, 과거 월·현재 월·미래 월·월말/윤년·희망일 끝 경계.
6. 기존 수동 다일 예약의 같은 시간대 반복 동작, 최초 계획·실적·CAPA·내보내기 회귀.
7. 미리보기 비저장, 시간 경과·기준 변경·다른 팀원 등록 후 확정 거부.
8. 일괄 저장 중 실패 롤백 및 재확정 중복 방지, 등록자 식별과 삭제 권한.
9. 관리자/팀원 권한, 화면 입력·미리보기·취소·확정, 기존 메뉴와 모바일 유지.
10. 다중 세션에서 편성 중 조회 가능 여부 및 두 사용자의 동시 확정 충돌 처리.

운영 반영 전에 기존 DB를 검증 백업하고 코드 변경을 구분하여 보존한다. 테스트는 별도 DB에서 수행하며 실제 운영 예약을 생성/삭제해 검증하지 않는다. 전체 기존 테스트와 새 테스트가 통과하고 코드 검토를 마친 뒤 자동 실행 작업을 재시작한다. 운영 DB의 기존 업무 데이터와 계정 보존을 확인한다.

## 10. 이번 단계의 산출물과 다음 단계

이 문서는 설계 산출물이며 자동 편성 메뉴·API·로직 구현 완료를 의미하지 않는다. 현재 앱의 런타임이나 운영 DB는 이 문서 작성으로 변경하지 않는다.

사용자가 문서의 설계와 제안 세부 사항을 승인하면 구현 계획을 작성해 검토받고 실행 방식을 확정한 뒤 구현한다. 실제 시험시간 표가 없다면 관리자가 기준시간을 직접 등록하는 화면으로 시작하며, 임의 시간으로 운영 일정을 만들지 않는다.
