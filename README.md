# 시험실 운영관리

## 현재 버전

시험 등록·수정 팝업에는 상태 선택란을 표시하지 않는다. 신규 등록은 내부적으로 `계획`으로 저장하고, 수정 시에는 기존 상태를 보존한다. 변경 사유는 수정 시 필수로 입력하고 변경 이력에 남긴다. 다른 화면의 상태 표시·필터와 오늘의 시험 현황 팝업 기준은 그대로 유지한다.

로그인 또는 로그인 상태로 앱에 진입하면 한국시간 오늘의 실제 예약 구간이 있는 `계획`·`진행` 시험을 팝업으로 한 번 표시한다. 검색 날짜·필터와 무관하며 시험실·시험 항목·프로젝트·담당자·오늘 예약 시간을 보여 준다. 완료·취소 시험, 일반 시험의 비가동일은 제외하고 연속시험은 야간·주말·공휴일에도 포함한다. 대상이 없으면 표시하지 않는다. 상태는 등록값을 표시할 뿐 자동 변경하지 않으며, 15초 동기화나 메뉴 이동으로 팝업이 반복되지 않는다.

과거 가동일수 기반 자동 일정 생성 기능은 사용자 요청으로 제거했다. 직접 `시험 등록`은 유지하며, 2026-10-23 추가한 `자동 시험 일정 편성`은 총 필요 가동시간 기반의 별도 기능이다. 아래의 월별 자동 편성 사용법을 참고한다. 과거 확정 시험과 실적·변경 이력·기준계획은 그대로 유지한다.

일반 설비의 여러 날 예약은 공휴일을 건너뛰고 운영일마다 같은 시간대를 사용한다. 실가동 시간은 시험별 휴식 규칙을 따른다. 단품 대상내구 시험·SN 커브 추출시험은 연속 24시간이다. 성능시험은 단품 대상내구 시험실 전용이며 기본 운영시간·휴식·공휴일 제외 기준을 적용한다. Glass Wool 내구는 열가진 #1·#2의 기본 운영시간·휴식·공휴일 제외 기준을 적용한다. 엔진의 서로 다른 두 시험 종류 동시 예약 예외는 기존 기준을 유지한다.

제거 전 소스 백업과 과거 설계는 `docs/auto-planner.md`에 기록했다. 해당 문서는 재추가 참고용이며 현재 앱의 기능 설명이 아니다.

연간·월간·주간·일간 보기를 제공한다. 연간 가동계획은 12개 월별 캘린더에 날짜별 시험 건수와 실적 입력 표시를 보여 주며, 월 제목을 누르면 월간 보기, 날짜를 누르면 일간 보기로 이동한다. 연간 화면 하단에서 같은 기간의 설비별 계획·실적·CAPA를 확인한다.

기존 조회 메뉴 상단 `검색 시작일`·`검색 종료일`에 날짜를 입력하고 `구간 검색`을 누르면 종료일 전체를 포함한 기간으로 조회한다. 검색 구간은 조회 메뉴와 보기 모드를 바꿔도 유지한다. 시작일과 종료일이 같으면 하루 조회이며, 연도를 넘는 구간과 윤년을 지원한다. 조회는 2000~2100년 사이에서 최대 3660일(약 10년), 시험 예약 자체는 기존처럼 최대 366일이다. 새 자동 편성 메뉴는 조회 검색과 독립된 대상 월을 사용한다.

구간 검색은 시험계획·가동계획·CAPA·엑셀 내보내기·해당 월들의 기준계획 목록에 적용된다. 운영 설정에서는 해당 구간의 공휴일과 설비 정지 일정을 표시하며, 팀 계정과 기본 운영 설정은 전체 설정을 유지한다. 31일보다 긴 검색 구간은 월별 작은 캘린더로 표시하고 구간 밖 날짜는 선택할 수 없다. 공휴일은 선택 구간에 포함된 모든 연도를 한국천문연구원 API로 확인한다.

`초기화`를 누르면 현재 기준 날짜와 보기 모드로 돌아온다. 기준 날짜 변경, `오늘`, 연간 캘린더의 월·일 클릭도 구간 검색을 해제하고 해당 날짜로 이동한다. 구간 검색 중 이전·다음 버튼은 같은 일수만큼 앞·뒤로 이동한다.

회사 내부망용 공동 일정관리 앱이다. 현재 노트북에서는 localhost 검토용으로 실행한다.
운영 서버를 선정하고 사내 접속 및 HTTPS를 구성하기 전에는 6인 배포 완료 상태가 아니다.
Codex 앱이 종료돼도 웹 서버가 실행 중이면 사용할 수 있다. 호스트 PC가 종료되면 사용할 수 없다.

## 실행

Windows 사내 운영 서버 설치 패키지는 `deploy/windows/README.ko.md`를 참고한다. 자동 실행·일일 백업 스크립트와 IIS HTTPS 프록시 예시를 제공하며, 서버 정보/인증서/사내 접속 범위를 확인한 후 설치해야 한다. 운영 DB·API 키는 설치 ZIP과 분리해 안전하게 이전한다.

Node.js 24 LTS와 pnpm 또는 npm이 필요하다.

```powershell
npm install
npm start
```

기본 주소는 http://127.0.0.1:4317 이다. 포트 사용 중이면 환경변수 PORT를 다른 값으로 지정한다.
이 노트북에서는 `Start-Lab.ps1`로도 실행할 수 있다.
첫 화면에서 운영 PC의 관리자를 등록하고 운영 설정에서 나머지 팀원 계정을 등록한다.
계정은 실제 사용자가 직접 정하며 공용 기본 비밀번호는 없다.

## 데이터

- 국가 공휴일·대체공휴일은 `src/holidays.mjs`에 2026·2027년 자료를 내장한다(2026-10-12 확인). 인증키를 등록하면 한국천문연구원 `getRestDeInfo` API 자료가 해당 연도의 내장 자료를 대체한다. 추가 등록한 공휴일은 유지한다.
- 월간·주간·일간 캘린더에 공휴일 이름, 기본 가동일수와 공휴일 제외 일수를 표시한다. 기본 가동일수는 운영 요일 기준이며 설비 정지나 주말 추가 예약은 일수가 아닌 CAPA 시간에 반영한다.
- 일반 설비 및 열가진 시험은 공휴일을 현재 계획·가용시간에서 제외한다. `주말 포함`도 공휴일을 포함하지 않는다. 단품 대상내구 시험·SN 커브 추출시험은 공휴일에도 24시간 연속 가동한다. 같은 시험실의 성능시험은 공휴일을 제외한다.
- 관리자는 `운영 설정 → 공휴일 추가`에서 임시공휴일을 등록하고 추가한 공휴일을 삭제할 수 있다. 국가 공휴일 자료는 삭제할 수 없다. 목록은 날짜 선택기의 연도를 따른다.
- 공휴일 지정 전에 등록된 예약과 실적·최초 계획·기준계획은 보존한다. 현재 계획은 공휴일을 건너뛰며, 이미 입력되었거나 실제로 수행된 가동실적은 공휴일 지정으로 차감하지 않는다. 공휴일에 남은 예약은 시험계획에서 조회·수정·취소할 수 있다.
- 관리자는 `운영 설정 → 공휴일 자동 갱신 → 인증키 등록`에서 공공데이터포털의 한국천문연구원 특일 정보 인증키를 등록하거나 변경한다. 저장한 키는 화면·조회 API에 반환하지 않으며 Git에서 제외된 서버 SQLite에만 저장한다. 인코딩된 키와 디코딩된 키 모두 입력할 수 있다.
- 서버 시작 시 현재 연도와 다음 연도를 확인하고, 이후 서버가 켜져 있는 동안 6시간마다 확인하여 마지막 조회에서 24시간이 지난 연도 자료를 갱신한다. 캘린더에서 선택한 연도와 앞뒤 연도도 조회한다. `지금 갱신`은 관리자가 즉시 다시 조회할 때 사용한다.
- 조회 실패·응답 오류·빈 자료·불완전한 자료는 캐시를 덮어쓰지 않는다. 마지막 공식 자료 또는 내장 자료를 계속 사용하며 오류를 운영 설정에 표시한다. 실패한 연도의 자동 재조회는 최소 1시간 간격으로 제한한다. 아직 발표되지 않은 미래 연도는 자료 미등록 경고를 표시한다.
- 인증키와 공휴일 캐시는 서버 DB 및 백업에 포함된다. 백업 접근 권한을 관리하고 Git에 올리지 않는다. 다른 PC에서 코드만 pull하면 인증키는 옮겨지지 않으므로 새 서버에서 키를 등록해야 한다. 공공데이터포털의 승인 기간·만료 상태는 포털에서 확인한다.

- 운영 데이터: `data/lab.sqlite`. 데이터베이스는 서버 로컬 디스크에 둔다.
- 기존 N:의 엑셀은 읽기 참고 자료이며 수정하거나 자동 이관하지 않았다.
- 월간·주간·일간 화면은 같은 서버 데이터를 읽는다.
- 기본 예약은 1시간이며 휴식시간 처리를 위해 30분 경계 입력을 허용한다.
- 일반 설비의 여러 날 예약은 매일 동일한 시간대의 운영일 예약이다.
- 단품 대상내구 시험·SN 커브 추출시험은 입력한 시작부터 종료까지 야간·주말 포함 연속 예약이다. 성능시험은 예외로 기본 운영시간을 적용한다. 시험실 자체의 CAPA 가용시간은 24시간이며 성능시험 점유시간은 운영시간에서 휴식을 뺀 시간만 계산한다.
- 열가진 혼합 CAPA는 기본 가용시간에 연속시험이 사용한 휴식 구간만 더한다.
- CAPA는 현재 설정 기준이다. 운영기준 개정 이력별 과거 분모 재현은 추가 보완 대상이다.
- 실적은 예약 내 실제 기간 또는 명시적인 0시간으로 입력한다. 중간 정지를 여러 구간으로 기록하는 기능은 현재 제공하지 않는다.
- 최초 계획은 변경 이력에, 월간 확정 시점은 기준계획에 별도로 남는다.
- 화면의 다른 팀원 변경 확인 주기는 15초이며 새로고침으로 즉시 확인할 수 있다.

## 백업과 복구

```powershell
npm run backup
```

SQLite 온라인 백업 API로 일관된 백업을 만들고 무결성을 검사한다.
백업은 `data/backups/`에 생성된다. 별도 백업 디스크로 보관하도록 운영 담당자가 설정한다.
일일 자동 백업 예약은 운영 호스트 선정 후 Windows 작업 스케줄러에서 구성한다.
복구할 때 서버를 종료하고 기존 `data` 폴더 전체를 보존한 뒤 백업 DB를 새 `data/lab.sqlite`로 배치하고 다시 실행한다.
기존 WAL 파일을 새 백업과 섞지 않는다. 백업에는 계정과 세션도 포함되므로 접근 권한을 제한한다.

## 사내 운영 전 확인

등록·수정 폼은 차종/프로젝트를 맨 위에 표시하고 별도 시험명 입력을 받지 않는다. 웹 폼에서 저장할 때 선택한 시험 종류를 시험명으로 사용한다.
이 변경은 기존 예약과 최초 이력을 일괄 수정하지 않는다. 기존 예약은 사용자가 수정 저장할 때 현재 시험명이 선택한 시험 종류로 갱신된다.

엔진동력계실 #1·#2의 신규 시험 종류는 배압 시험 및 토출/방사음 시험이다. 서로 다른 두 종류만 동시 예약할 수 있으며 동일 종류 중복과 설비 정지 충돌은 막는다.
변경 전 엔진 시험·이음 시험·기류음 시험 예약은 보존하며, 기존 종류 그대로 수정할 수 있지만 새 예약에는 선택할 수 없다. 기존 종류는 동시 예약 예외에 해당하지 않는다.
열가진 내구시험실 #1·#2의 기타 성능시험은 일반 휴식 1.5시간을 적용한다.
설비별 최초 계획·계획·실적 가동시간은 겹치는 가동 구간을 한 번만 계산해 동시 시험을 이중 집계하지 않는다.

실적 영역에는 프로젝트명을 표시하고, 프로젝트 미지정 시 시험명을 표시한다.
시험 상세의 `실적 삭제`에서 확인 후 실적만 삭제할 수 있다. 계획·최초 이력은 유지되며 미입력 상태와 CAPA/달성률이 다시 계산된다.
로그인한 팀원은 기존 공동 수정 정책과 동일하게 실적을 삭제할 수 있다. 개별 실적 삭제에는 별도 실행 취소 기능이 없으며 필요하면 실적을 다시 입력한다.

중복 예약은 전용 팝업으로 알린다. 확인 후 작성 중인 예약 폼과 입력값은 유지한다.
가동계획의 각 시험 카드 아래에 날짜별 실적 시간, 0시간 실적 또는 미입력을 표시한다.
단품 대상내구의 자정을 넘는 실적은 해당 날짜 구간으로 잘라 표시하고 하루 끝을 24:00으로 표시한다.

가동계획의 시험실별 요약은 선택한 월/주/일의 최초 계획·실적·달성률을 표시한다.
최초 계획은 첫 등록 이력 기준이며, 이후 수정 또는 취소해도 최초 계획 합계에는 남는다.
실적 미입력은 0시간 실적과 구분하고 입력분 합계 및 잠정 달성률로 표시한다. 취소 시험은 미입력 건수에서 제외한다.
신규 등록은 당시 휴식·운영 규칙을 적용한 가동 구간을 보존한다. 이 기능 도입 전 등록 이력은 최초 기본 운영 규칙으로 계산하므로, 과거에 다른 운영 규칙을 사용했다면 확인이 필요하다.

엔진동력계실 #1·#2 및 유동저항 시험실은 예약별 `주말 포함`을 선택할 수 있다.
시작일 또는 종료일에 주말을 선택하면 자동 적용된다. 주말 셀을 클릭하면 해당 날짜로 입력한다.
주말에도 운영시간과 휴식시간을 적용한다. 기본 평일 CAPA는 유지하며 주말 예약의 실제 계획 가동 구간만 가용 시간에 더한다.
주말 포함을 선택하지 않은 기존 다일 예약은 주말을 계속 건너뛴다. 열가진 및 단품 대상내구 운영 규칙은 바꾸지 않는다.

1. 항상 켜 두는 서버/PC와 회사 IT 담당자를 정한다.
2. 사내 HTTPS 역방향 프록시를 준비한다. `COOKIE_SECURE=1`로 보안 쿠키를 활성화한다.
3. 허용된 사내 주소에만 접속을 열고 외부 공개는 하지 않는다.
4. 웹 서버 상시 실행과 일일 백업 작업을 등록한다.
5. 팀원 6명의 실제 접속, 로그인, 중복 예약 거부와 백업 복구를 확인한다.

개발 서버는 기본 localhost에만 바인딩한다. 운영 환경 변경은 현재 실행에 자동 적용하지 않는다.
비밀번호 변경/계정 비활성화, 복수 실적 구간, 승인 워크플로는 후속 보완 항목이다.

## 전체 시험 일정 일괄 삭제

관리자 계정의 **운영 설정 → 전체 시험 일정 삭제…**에서 사용한다. 조회 기간이나 검색 조건과 관계없이 모든 예약(취소 포함)과 실적·변경 이력·기준계획·자동 배치 내역이 삭제된다. 계정·운영 기준·공휴일/API 인증키·설비 정지는 유지한다. 대상 건수를 확인하고 `전체 시험 일정 삭제`를 정확히 입력해야 실행된다.

삭제 직전에 DB 폴더의 `backups/`에 전체 SQLite 백업을 만들고 무결성을 검증한다. 백업 실패 또는 검토 후 시험 데이터 변경 시 삭제하지 않는다. 삭제는 하나의 트랜잭션으로 실행한다. 완료 화면에 백업 파일명이 표시된다.

복구는 서버를 종료한 상태에서 관리자가 백업 DB를 복원해야 한다. 복원하면 백업 이후의 모든 데이터 변경도 되돌아가므로 현재 DB를 먼저 보관한다. 백업에는 계정·세션·API 인증키가 포함되어 있으므로 외부 공유와 Git 추가를 금지한다. 앱 내 복원 기능은 제공하지 않는다.

## 관리자 팀 계정 관리

운영 설정의 **팀원 등록**에서 관리자가 이름·초기 아이디·초기 비밀번호·권한을 지정한다. 사용 중인 계정은 관리자 포함 6명까지이며, 정원에 도달하면 사유를 표시한다. 아이디는 영문·숫자 및 `. _ -`를 사용한 3~40자, 비밀번호는 10~200자이다.

각 계정의 **ID·비밀번호 설정**에서 이름·아이디·권한을 수정하거나 새 비밀번호를 지정한다. 새 비밀번호를 비워 두면 기존 비밀번호를 유지한다. 기존 비밀번호는 조회할 수 없으며 해시만 저장한다. 아이디·비밀번호·권한 변경 시 해당 계정의 모든 기존 세션을 해제하므로 다시 로그인해야 한다. 다른 계정의 접속은 유지된다.

**삭제**는 확인 후 계정을 비활성화하고 해당 계정의 접속을 해제하는 방식이다. 삭제된 계정은 정원에서 제외하고 신규 시험의 담당자로 지정할 수 없지만, 기존 시험·실적·변경 이력·기준계획 및 담당자 식별자는 보존한다. 기존 시험 수정 시 삭제된 담당자를 그대로 유지하거나 사용 중인 담당자로 변경할 수 있다. 삭제된 아이디는 재사용하지 않으며 복원 기능은 제공하지 않는다. 본인 계정 삭제와 마지막 관리자 삭제·일반 팀원 전환은 서버에서도 차단한다.

기존 DB는 서버 시작 시 `users.active`와 `users.version` 열을 기본값 1로 추가하여 기존 계정을 유지한다. 계정 설정 화면은 버전을 함께 전송하여 다른 관리자의 변경을 오래된 창에서 덮어쓰면 409 오류로 차단한다. 직접 API를 사용하는 기존 클라이언트는 버전 생략을 허용하므로 충돌 검사가 필요하면 최신 `version`을 전송한다. 지연된 계정 등록·수정 요청도 본문 수신 후 관리자 세션·CSRF·권한을 다시 검사한다.

업데이트 전 DB를 백업하고 서버를 재시작해야 한다. 5개 독립 세션의 동시 사용 및 계정 관리 브라우저 테스트는 별도 테스트 DB를 사용하며, 실제 팀원 PC 접속은 별도로 확인해야 한다.

## 개별 시험 삭제

시험 상세의 **시험 삭제**를 누르면 `정말로 삭제하시겠습니까?` 확인 팝업을 표시한다. 취소하면 삭제 요청을 보내지 않는다. 삭제 권한은 관리자 또는 최초 일정 등록자에게만 있다. 담당자나 최근 수정자라는 이유로는 삭제할 수 없다. 최초 등록자를 확인할 수 없는 시험은 관리자만 삭제한다. 다른 팀원에게는 버튼을 숨기며 서버에서도 삭제 준비 조회와 직접 DELETE 요청을 차단한다. 확인하면 해당 시험의 계획·가동 구간·실적·변경 이력만 삭제하며 다른 시험, 계정, 설정, 공휴일, 설비 정지, 확정 기준계획 스냅샷은 유지한다. 삭제한 시험은 현재 일정·실적 집계 및 최초 계획 집계에서 제외되지만, 이전에 확정한 기준계획에는 당시 기록이 남는다.

서버는 삭제 전에 `data/backups`에 전체 DB를 백업하고 무결성을 검사한다. 백업 실패, 로그인 만료, 다른 팀원의 해당 시험/실적 변경이 감지되면 삭제하지 않는다. 삭제 대상의 스냅샷 revision과 인증/CSRF를 백업 전후 확인하고 실제 삭제는 하나의 트랜잭션으로 실행한다. 실패 시 상세 창에 오류를 표시하고 버튼을 다시 사용할 수 있다. 다른 시험만 변경된 경우에는 삭제를 막지 않는다. 확인 정보를 불러오는 동안 상세를 닫거나 다른 창으로 바꾸면 이전 시험의 확인 팝업을 띄우지 않는다. 이미 확인한 삭제가 처리 중일 때 다른 편집 창을 열어도 새 창의 입력은 닫거나 지우지 않는다.

삭제 후 앱 내 실행 취소 기능은 없다. 필요하면 관리자가 삭제 전 백업으로 복원해야 하며, 전체 DB 복원은 백업 이후의 다른 변경도 되돌리므로 현재 DB를 별도 보존한 뒤 처리한다. 백업은 계정과 API 인증키를 포함할 수 있으므로 외부 공유하거나 Git에 추가하지 않는다.

## 월별 자동 시험 일정 편성

기존 **시험 계획 수립**은 그대로 사용한다. 새 **자동 시험 일정 편성**은 총 필요 가동시간을 기준으로 지정 시험실에 월별 시험을 배치하는 추가 기능이다. 외부 AI를 사용하거나 소요시간을 추측하지 않는다.

1. 관리자는 **운영 설정 → 시험항목별 기준시간**에서 시험실/항목별 시간을 0.5시간 단위로 입력하고 저장한다. 초기에는 모든 시간이 미등록이다. 사용 체크를 끄면 자동 편성에서만 제외한다.
2. **자동 시험 일정 편성**에서 현재/미래 월을 선택하고 프로젝트·시험실·시험항목·담당자를 입력한다. 기준시간을 불러오며 행에서만 변경할 수도 있다. 최대 30개이며, 행의 변경은 기준표를 바꾸지 않는다.
3. **빠른 배치**는 입력 순서, **완료 희망일 기준**은 희망일이 빠른 순서로 처리한다. 희망일 기준에서는 각 행의 희망일이 필수다.
4. **편성안 만들기**로 일별 구간·시작/종료·총 가동시간을 검토한다. 모든 항목이 배치되었을 때 **일괄 확정 · 캘린더에 등록**을 누른다. 미리보기만으로 시험이 등록되지 않는다.

서버 현재 시각 다음 30분 경계부터 한국시간 월 경계 안에서만 배치하며 기존 일정은 이동/삭제하지 않는다. 일반 시험도 첫날 잔여시간부터 다음 운영일에 이어 가동한다. 기본 운영 기준에서 15시간은 첫날 10.5시간과 다음 날 4.5시간(14:00 종료)이다. 중간 운영일에 충돌하면 빈 날을 건너뛰어 쪼개지 않고 시작 후보를 다시 찾는다. 기존 공휴일 API/캐시·휴식·주말 옵션·열가진/24시간 시험·엔진 동시 가동 예외를 그대로 적용한다. 일반 시험 연도의 공휴일 자료가 확인되지 않으면 확정하지 못한다.

편성안은 생성 계정만 확정할 수 있고 30분 후 또는 서버 재시작 시 미확정안이 사라진다. 관련 일정·실적·설정·계정 변경 또는 시작 시각 경과 시 다시 편성한다. 같은 확정 요청의 재시도는 같은 결과를 반환한다. 모든 시험·구간·등록자 이력·배치 결과는 한 트랜잭션에 저장한다. 전역 최적 배치는 보장하지 않으며 3초/후보 100,000개 탐색 한도에 도달하면 한도 메시지를 표시한다.

자동 시험도 기존 화면에서 수정/실적/권한에 따른 삭제가 가능하다. 기간·시험실·종류 변경은 연속 구간을 서버에서 재계산하며, 상세에서 변경 후 계획 가동시간과 당시 요구시간을 구분해 확인한다. 변경 사유는 이력에 남긴다. 실적은 실제 기간으로 별도 계산한다. 자동 편성 예약은 일별 `plannedWindows`를 가지며 이전 수동 예약의 동일 시간대 반복 방식은 바뀌지 않는다. 기존 삭제 확인·백업·관리자/최초 등록자 권한도 유지한다. 전체 일정 삭제는 새 편성 등록 이력도 제거하지만 기준시간 설정은 보존한다.

업데이트 전 검증 백업과 서버 재시작이 필요하다. 기존 Windows 배포 ZIP은 이전 스냅샷이므로 이 기능을 포함하지 않는다. 실제 시험별 기준값과 다른 물리 PC 접속은 관리자가 별도로 확인해야 한다.
